# Эмулятор командной строки UNIX (Вариант 30)

## Общее описание

Эмулятор оболочки UNIX-подобной операционной системы с графическим
интерфейсом (tkinter), реализованный в рамках дисциплины
«Конфигурационное управление».

- **Вариант:** №30
- **Студент:** Эльдяшев Павел Игоревич
- **Группа:** ИКБО-64-25
- **Вуз:** РТУ МИРЭА, 3 семестр (осенний) 2026/2027 учебного года

Эмулятор работает с виртуальной файловой системой (VFS), которая загружается
из директории на диске в память. Все операции (в том числе `rm` и `mv`)
выполняются только в памяти — файлы на диске не изменяются.

## Описание функций и настроек

### Интерфейс (этап 1)

- GUI: поле вывода (ошибки подсвечены красным) и строка ввода с приглашением
  `имя_vfs:/текущая/папка$`. Клавиши ↑/↓ листают историю ввода.
- Заголовок окна содержит имя VFS: `Эмулятор - [имя_vfs]`.
- Парсер разделяет ввод по пробелам и раскрывает переменные окружения реальной
  ОС: `$HOME`, `${HOME}`. Неизвестная переменная заменяется пустой строкой.
- Ошибки выполнения команд (неизвестная команда, неверные аргументы)
  выводятся в окно.

### Параметры командной строки (этап 2)

| Параметр | Описание |
| --- | --- |
| `--vfs <путь>` | путь к физическому расположению VFS (директория на диске) |
| `--script <путь>` | путь к стартовому скрипту |
| `--headless` | без окна: вывод в stdout, код возврата 1 при ошибке (для автоматических тестов) |

- При запуске выводятся отладочные строки `[debug] ключ = значение` для
  всех параметров.
- **Стартовый скрипт** выполняется построчно; на экран выводятся и ввод
  (с приглашением), и вывод, как в диалоге. Пустые строки и строки, начинающиеся
  с `#`, пропускаются. **При первой ошибке скрипт останавливается**, выводится
  `script stopped: error in line N`. Ошибка чтения файла скрипта также
  сообщается. После успешного скрипта в окне можно продолжить работу.
- `conf-dump` — вывести параметры эмулятора в формате `ключ=значение`.

### VFS (этап 3)

- Источник VFS — директория на диске. Она один раз читается в память
  (двоичные файлы хранятся как `bytes`), дальше диск не используется.
- Ошибки загрузки (путь не найден, путь не является директорией) показываются
  в окне; эмулятор продолжает работу с VFS по умолчанию.
- Без `--vfs` создаётся небольшая VFS по умолчанию в памяти.
- Если в корне VFS есть файл `motd`, его текст выводится при старте.

### Команды (этапы 1, 4, 5)

| Команда | Описание |
| --- | --- |
| `ls [-l] [путь]` | содержимое папки или файла; папки помечены `/`; `-l` — права, размер, имя |
| `cd [путь]` | сменить папку (`.`, `..`, абсолютные и относительные пути); без аргумента — корень |
| `clear` | очистить экран |
| `echo [текст...]` | вывести аргументы |
| `who` | пользователь, терминал, время начала сеанса |
| `rm [-r] путь...` | удалить файлы; папки — только с `-r`; текущую папку удалить нельзя |
| `mv источник приёмник` | переименовать или переместить; если приёмник — папка, объект кладётся в неё |
| `conf-dump` | параметры эмулятора в виде `ключ=значение` |
| `exit` | завершить работу |

### Структура репозитория

```
src/            исходный код (main.py, shell.py, commands.py, vfs.py, ...)
tests/          unit-тесты и скрипты реальной ОС (tests/os/stage*.sh)
examples/vfs/   примеры VFS: minimal, multi, deep (4 уровня вложенности)
examples/scripts/  стартовые скрипты эмулятора (*.emu)
Makefile, run.sh   запуск и тесты
```

## Команды для сборки проекта и запуска тестов

Требуется Python 3.10+ с модулем tkinter (для GUI; для тестов и режима
`--headless` tkinter не нужен). Сборка не требуется.

```
make run                     # запуск окна без параметров
make test                    # unit-тесты
make test-os                 # скрипты реальной ОС для всех этапов
./run.sh --vfs examples/vfs/deep --script examples/scripts/stage4.emu
```

Скрипты реальной ОС: `tests/os/stage2.sh` (все параметры командной строки),
`stage3.sh` (разные VFS и ошибки загрузки), `stage4.sh` и `stage5.sh`
(команды и ошибки). Они запускают эмулятор с `--headless` и проверяют
коды возврата.

## Примеры использования

Запуск окна с VFS из папки и стартовым скриптом:

```
python3 src/main.py --vfs examples/vfs/multi --script examples/scripts/stage5.emu
```

Фрагмент диалога (`examples/vfs/deep`):

```
Deep VFS: 4 levels of nesting.
deep:/$ ls
home/  motd  projects/
deep:/$ ls -l /projects/app/src
-rw-r--r--       14 main.txt
-rw-r--r--        7 util.txt
deep:/$ cd projects/app
deep:/projects/app$ mv src/util.txt docs
deep:/projects/app$ ls docs
guide.txt  util.txt
deep:/projects/app$ rm docs
rm: cannot remove 'docs': is a directory
deep:/projects/app$ rm -r docs
deep:/projects/app$ echo $HOME
/home/student
deep:/projects/app$ cd /nope
cd: /nope: no such file or directory
deep:/projects/app$ exit
```

Примеры ошибок: неизвестная команда — `foo: command not found`;
неверные аргументы — `ls: too many arguments`, `mv: missing operand`;
ошибка VFS — `VFS load error: 'x': no such file or directory`.
